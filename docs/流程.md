## 内容笔记
## 一、本节核心要点（讲师明确强调的）
+ **充电器不能混用**：小车底盘充电器是12.6V/3A，射击模块充电器是8.4V/1A，混用会损坏设备。这是最常见的硬件错误。
+ **四个USB接口不能插错**：机载电脑上的四个USB接口有特定用途，激光雷达接口和射击模块接口的线插混会导致程序报错（找不到接口、找不到模块）。这是后期运行时报错的第一排查点。
+ **HDMI线严禁热插拔**：显示器与机载电脑之间的HDMI线必须在断电状态下插拔，带电操作会导致屏幕损坏，无法正常显示。
+ **地图保存时不要改主文件名**：保存地图时，最稳妥的做法是修改地图所在目录下的文件名（如将`my_lab`改成`my_lab2`），而不是修改`save_map.launch`中的默认名称，否则后面代码调用会出问题。
+ **PID调试核心思路**：先调KP，把系统调到临界震荡状态，再把KP乘以0.7或0.8作为最终值；然后调KI，一点点增加，直到消除稳态误差。这是让瞄准更丝滑的核心方法。
+ **终点进入要用速度指令硬滑进去**：因为导航算法会把终点（角落）识别为不可行区域，无法自动驶入，需要用代码直接给底盘发线速度指令让小车滑进去。滑行距离由速度大小和时间控制。

本课程按“硬件组装→调试注意事项→功能模块（建图/识别/射击）→代码实现→单独调试→语音集成→整体启动”的逻辑展开，属于操作+代码讲解课。

**结构梳理：**

1. **硬件组装与开箱**：M1ATK无人车主体、射击模块、配件说明
2. **安装与使用注意事项**：充电器区别、USB接口区分、HDMI热插拔禁令、电量监控
3. **功能模块介绍**：建图、自主导航、识别（模板匹配/二维码）、射击
4. **建图功能代码详解**：gmapping建图脚本、键盘控制、地图保存与改名技巧
5. **识别功能讲解**：模板匹配（环形码）与二维码识别（旋转靶/移动靶）
6. **主程序（任务挑战赛）代码逐段分析**：区域一（环形码瞄准射击）→区域二（旋转码瞄准射击）→区域三（移动靶瞄准射击）→终点处理
7. **单独调试方法**：如何分离各区域代码进行独立测试、PID调参方法

9. **启动脚本说明**：启动底盘、射击模块、导航、摄像头、模板匹配、语音等相关节点

## 三、涉及知识点（逐个详写）
### 1. 充电器使用规范
+ **定义 / 含义：** 机器人底盘和射击模块各自有专用的充电器，电压电流不同，不能混用。
+ **核心特征：**
    - 底盘充电器：12.6V，3A；底盘电量低于10.5V需充电，充到12.6V左右满电
    - 射击模块充电器：8.4V，1A；射击模块电量低于7V需充电，最高8.4V
+ **原理 / 机制：** 防止因电压过高或电流不匹配烧毁电池或充电电路。
+ **典型应用 / 示例：** 使用前必须看充电器标签上的电压电流参数，确认后再插。
+ **判断关键词 / 答题用法：** “注意区分”“不要混用”“一定看一下这个电压和电流”
+ **考点提示 / 易错点：** 学生经常搞混，直接导致射击模块或底盘损坏。讲师特意强调“用的时候一定要看一下”。

### 2. 机载电脑USB接口与HDMI接口规范
+ **定义 / 含义：** 机载电脑（NUC）上四个USB接口分别连接激光雷达和射击模块，HDMI接口连接显示器。
+ **核心特征：**
    - 左上方的一个USB接口连接激光雷达的数据线
    - 橙色（或特定标识）的USB接口连接射击模块（白色数据线）
    - 这四个USB接口绝对不能插混，插混会导致程序运行时报错“找不到接口”“找不到模块”
    - 显示器HDMI线：连接机载电脑的HDMI接口
    - HDMI线禁止热插拔：必须先断电再插拔，否则可能损坏屏幕
+ **原理 / 机制：** 系统通过USB端口识别设备，插错后设备无法被正确加载；HDMI热插拔会产生静电或电压冲击，烧坏显示驱动板。
+ **典型应用 / 示例：** 讲师举例：很多同学后面遇到报错“找不到激光雷达”或“找不到射击模块”，第一件事就是检查USB线是否插对。
+ **判断关键词 / 答题用法：** “一定不要整混了”“这是大家后面经常遇到的一个问题”“带电操作可能会引起屏幕的损坏”
+ **考点提示 / 易错点：** 学生最容易犯的错误是插错USB口和热插拔HDMI，这两个是硬件排障的优先检查项。

### 3. 建图功能（gmapping）及其操作流程
+ **定义 / 含义：** 通过控制小车在未知环境中移动，利用激光雷达、IMU等传感器数据，构建环境地图的过程。
+ **核心特征：**
    - 使用`gmapping`算法；由`launch`脚本批量启动多个节点
    - 脚本内容：启动roscore、打开相关launch文件（IMU、建图、可视化地图）、启动键盘控制节点（`keywords/keyboard`）
    - 键盘控制键位（以K为中心）：
        * I：前进；逗号：后退
        * 原地左转：J；原地右转：L
        * 左前：U；右前：O；左后：M；右后：句号
        * 大写字母：加速/增大转速
+ **分类 / 构成：** 操作流程分为三步：启动建图→控制小车移动扫描→保存地图
+ **典型应用 / 示例：**
    - 讲师推荐去B站搜“M1ATK建图”视频辅助学习
    - 讲师给了一个指令：直接在终端输入`./gmapping`（点杠gmapping脚本）即可启动建图功能
    - 保存地图指令：`roslaunch robot_slam save_map.launch`（注意不是`robot slam`，是两个单词之间没有空格）
+ **判断关键词 / 答题用法：** “建图节点启动”“键盘控制”“保存地图”“点杠映射”
+ **考点提示 / 易错点：**
    - 注意文件夹名是`robot_slam`不是`robot slam`
    - 保存地图时，如果想保留旧地图，不要改`save_map.launch`文件里的default名称，而要去地图目录下把旧地图的文件名改成别的，这样一旦需要换回旧地图，把名字改回来即可
    - 不保留旧地图，新地图会直接覆盖旧地图，导致旧地图丢失

### 4. 地图保存与文件名管理（重点技巧）
+ **定义 / 含义：** 建图完成后，将地图保存为文件；后续导航时调用指定地图；地图文件位于特定目录下（`map`文件夹）。
+ **核心特征：**
    - 保存指令`save_map.launch`中有一个default参数，控制地图的默认名称（例如`my_lab`）
    - 如果之后又建了新地图并再次使用`save_map.launch`，新地图会覆盖掉名为`my_lab`的旧地图
    - 最佳做法：建好地图后，不修改default名称，而是把`map`目录下的旧地图文件（如`my_lab.yaml`和`my_lab.pgm`）改名为`my_lab2`、`my_lab3`等；下次想用哪张图，就把对应图的文件名改回`my_lab`
    - 这是因为后面的导航代码调用的是`my_lab`这个名字，不改名则无需更改代码
    - 讲师特意区分：**不要改launch文件**，改成了别的名字容易忘，且后面代码会找不到地图
+ **典型应用 / 示例：**
    - 如果建好地图A后觉得不错，不想被后续的地图B覆盖：将地图A文件改名为`my_lab_old`，然后建地图B并保存，此时系统会创建新的`my_lab`，地图A和B都存在且互不影响
    - 如果因为IMU不准或其他原因导致地图有偏移，可以重新建图来提高精度
+ **判断关键词 / 答题用法：** “推荐大家去改这个路径下这个目录下这个地图的新名字”“不要改这个（launch文件里的default）”“引起一系列不必要的麻烦”
+ **考点提示 / 易错点：** 学生容易直接改launch文件里的名字，结果忘记，导致程序跑不起来。讲师强调“改文件名”是最安全、最省事的方法。

### 5. 模板匹配识别（环形码）
+ **定义 / 含义：** 一种视觉识别方法，通过将图像中的物体与预先保存的模板进行比对，找到最匹配的物体（本课中用于识别任务点一和终点处的环形靶）。
+ **核心特征：**
    - 由话题`/fiducial_images`（或类似名称）传出识结果，包括：模板序号（`point_message.z`）、物体中心在图像中的X和Y值（`point_message.x`、`point_message.y`）、物体边框四个顶点在像素坐标中的值
    - 需要先“教”机器人识别目标：通过拍照给物体“框一下”，让机器人记住这个物体作为模板
    - 模板匹配识别到后，终端会显示`object 数字`（如object 113），这个数字就是模板序号
+ **原理 / 机制：** 图像分辨率为640×480像素，相机的中心点位于(320, 240)。如果能识别到物体，通过计算物体中心点与(320, 240)之间的像素偏移量，就可以判断武器（枪口）是否已经对准目标。
+ **典型应用 / 示例：**
    - 讲师现场演示：先启动相机节点（打开摄像头），终端显示`No object detected`；然后对物体进行“框选”（拍照建立模板），终端立刻显示`object 113`和四个顶点坐标，表明成功识别
    - 讲师特别指出：如果框选两次，可能同时出现`object 113`和`object 114`两个序号，说明识别到了两个模板；两个模板各有优缺点，需要后续调试决定用哪一个
+ **判断关键词 / 答题用法：**
    - “减去320”：因为画幅宽度640像素，中心在320处；识别到的物体X值减去320得到物体偏离中心的方向
    - “point_message.z”：代表模板序号（如113），在代码中与控制逻辑（`case`）匹配，以确定当前是否在对的目标进行瞄准
+ **考点提示 / 易错点：**
    - 注意模板序号（113、114）与代码中写的数字（如34）必须对应，如果不对应，则无法进入瞄准逻辑
    - 讲师提醒：大家在调试时，要保证自己拍到的模板序号与代码里的序号一致

### 6. 二维码识别（二维码/QR码识别）
+ **定义 / 含义：** 用于识别旋转靶和移动靶上的二维码。
+ **核心特征：**
    - 通过话题`/ar_pose_marker`（或类似名称）传出二维码的中心位置和ID号
    - 与模板匹配不同，二维码识别不需要预先“拍照教学”，可以直接读取二维码的ID（例如1、2、3……）
    - 返回的数据既包含ID号，也包含二维码在相机坐标系中的偏移（X方向、Y方向、Z方向）
+ **分类 / 构成：** 本课程中二维码靶分为两种：
    - 旋转靶（任务点二）：二维码在旋转靶面上，靶子本身不移动但旋转，所以瞄准时需要同时保证X和Y方向都对准中心
    - 移动靶（任务点三）：二维码在移动的靶车上，所以更强调跟踪性和响应速度
+ **典型应用 / 示例：**
    - 讲师介绍：在比赛时裁判会给出二维码ID号（例如旋转靶打几号、移动靶打几号），参赛者需要在代码中修改`id`变量
    - 移动靶因是动态的，要求机器人的跟踪性要好，主要调KP让响应更快
+ **判断关键词 / 答题用法：**
    - “X方向”和“Y方向”：对于旋转靶，不只靠X偏移来判断瞄准，还要看Y方向的偏移是否在允许范围内
    - `max_threshold`：最大误差阈值；`min_Y`和`max_Y`：Y方向的上下限阈值
    - 讲师特别强调：旋转靶如果只瞄X方向，Y方向不对的话就会打空，因为存在空间上的错位
+ **考点提示 / 易错点：** 二维码识别因为存在画面畸变，数据可能会“飘忽不定”，导致中心点定位不准；这是单独调试时可能出现的问题之一。

### 7. 射击功能与瞄准控制流程
+ **定义 / 含义：** 机器人在识别到目标之后，通过发送速度控制指令（/twist话题）进行微调旋转，使枪口与目标中心重合，然后执行射击（开火/关火）的操作。
+ **核心特征：**
    - 瞄准核心逻辑：将识别到的目标中心（X/Y）与相机画幅中心(320,240)对比，得到差值→将这个差值乘以一个比例系数→作为角速度发给底盘进行旋转微调
    - 射击输出：当误差小于设定的阈值（如10个像素点或0.07单位）时，认为已经瞄准到位，然后发送射击指令（开火），停留一定时长（0.08秒或0.1秒后再关火）
+ **分类 / 构成：**
    - 区域一（环形码）：只用X方向的误差（减320），因为环形靶通常是固定在平面上，水平对准后Y方向基本没问题
    - 区域二（旋转码）：同时需要X方向误差和Y方向误差，两个方向都在允许范围内才能射击
    - 区域三（移动码）：类似旋转码，但需要更快的跟踪响应（调高KP）
+ **原理 / 机制：** 本质上是一个比例控制器（P控制），也可以用PI控制器（加积分项）来让瞄准更丝滑、更精确，防止震荡或超调。
+ **典型应用 / 示例：**
    - 讲师演示了一个用PID控制微调的小车视频：可以看到小车车身在非常细微地左右调整，然后突然稳定（说明瞄准到位）
    - 讲师还提供了一个“物理偏移补偿”的例子：如果枪口是歪的（物理安装偏差），可以对代码中的中心点做偏移，例如把`-320`改成`-319`、`-318`或`-323`，以此来抵消物理偏移
+ **判断关键词 / 答题用法：**
    - `error > threshold`（误差大于阈值）→继续瞄准（发送旋转指令）
    - `error < threshold`（误差小于阈值）→瞄准到位，可以射击
    - `flag`标志位：用于控制每个区域是否已经完成了射击，避免重复射击或跳过射击
    - `case`变量：用于切换当前处于哪个任务区域（case=0对应区域一，case=1对应区域二，case=2对应区域三）
+ **考点提示 / 易错点：**
    - 比例系数（0.02/0.01/1.0等）需要反复调试：调太大容易震荡（左右来回转），调太小响应太慢
    - 误差阈值不能太小（会导致瞄准时间过长），也不能太大（会导致打偏）
    - 枪口物理偏移是很多同学“怎么调参数都打不准”的根本原因，需要在代码层面做偏移补偿

### 8. 单独调试方法
+ **定义 / 含义：** 将主程序（任务挑战赛完整流程）中的某一区域的功能单独拆分出来，在一个简化版的代码中独立测试该区域的识别、瞄准和射击，避免其他模块的干扰。
+ **核心特征：**
    - 在原功能代码中找到对应区域的回调函数（如`FD_CB`对应区域一的环形靶识别）
    - 复制一份代码，只留下该区域用到的识别函数（如`FD_CB`），把其他区域的回调函数（如`A2_CB`）注释或删除
    - 删除代码中的导航去往任务点的部分（如`go(goal_0)`），这样小车启动后不会移动，原地开始瞄准测试
    - 通过这种方式，可以单独判断是瞄准算法问题、参数问题还是物理枪口偏移问题
+ **典型应用 / 示例：**
    - 讲师建议：如果一区域（环形码）怎么也打不准，调参数也没效果，就单独拉出区域一的代码调试，先看瞄准逻辑本身是否正常
    - 调整方法：可以微调中心点偏移（减318、减323等），或者修改PID参数
+ **判断关键词 / 答题用法：** “把原始功能代码复制一份”“只留下第一个任务区域里的FD识别函数”“把这个导航函数删掉”
+ **考点提示 / 易错点：** 学生经常在整体流程中遇到问题却不知道是哪个区域出了毛病，单独调试是快速定位问题的关键方法。

### 9. PI（比例-积分）控制器
+ **定义 / 含义：** 一种更精准的瞄准控制算法，比单纯的P控制（比例控制）多一个积分项，可以消除稳态误差，使瞄准更平滑。
+ **核心特征：**
    - KP（比例系数）：决定响应速度，值越大响应越快，但过大会引起震荡
    - KI（积分系数）：决定消除稳态误差的能力，值越大消除越快但可能引发过冲
    - 输出限幅（最大输出/最小输出）：限制最终发出的速度指令的大小，防止旋转太快导致瞄准过度
+ **原理 / 机制：** 输出 = KP × 误差 + KI × 积分累加量（误差对时间的累积）
+ **典型应用 / 示例：**
    - 讲师提供了一个PID控制器的代码示例，并说明如何使用：
        * 先调KP，把机器人调到临界震荡状态（即目标准备后小车来回摇摆），记下这个KP值
        * 将KP乘以0.7或0.8作为最终KP值
        * 然后一点点增加KI，直到瞄准变得丝滑且没有稳态误差
        * 如果KI过大会导致过冲，需要同时调整限幅（最大输出/最小输出）
    - 讲师强调：如果不用PI控制器，只有简单比例控制，那就只调比例系数（一个数），调到理想状态即可
+ **判断关键词 / 答题用法：** “临界状态”“来回摇摆”“乘以0.7或0.8”“一点点去调KI”
+ **考点提示 / 易错点：** 如果不了解调参步骤，直接乱调，很容易越调越乱。讲师给出了明确的“两步走”流程：先调KP到临界再衰减，再加KI微调。

### 10. 终点处理（滑行进入）
+ **定义 / 含义：** 任务完成（三个靶都打完）后，小车需要导航到终点位置。但因为导航算法会误判终点区域（通常是角落）为不可到达区，导致小车在终点外围反复徘徊无法进入。
+ **核心特征：**
    - 解决方案：不依赖导航，直接给底盘发一个线速度控制指令（/twist话题），让小车靠速度硬“滑”进终点区域
    - 指令内容：通常是一个负的X方向速度（后退）加上一个正的Y方向速度（向左），合成一个斜向下的运动方向
    - 滑行时间：通过循环次数控制（例如循环15次，每帧10Hz，总共1.5秒）
    - 滑行速度和时间可调，以不撞到挡板、平稳滑入为准
+ **典型应用 / 示例：**
    - 讲师在代码中写了一个`endpoint_func`函数，专门实现这个功能
    - 因为任务点三到终点之间可能会有一段距离，讲师建议：在中间加一个“过渡点”，小车先导航到过渡点，再从过渡点用速度滑进终点
    - 讲师演示了具体的代码写法：`twist.linear.x = -0.1`、`twist.linear.y = 0.1`（速度值举例，需调试）
+ **判断关键词 / 答题用法：** “直接给底盘发送控制指令”“不用导航功能，直接发速度指令”“滑进去”
+ **考点提示 / 易错点：** 速度值不要太大，否则容易撞到挡板；速度值太小滑不动；可能需要加过渡点来提前调整位置。

### 11. 语音控制模块
+ **定义 / 含义：** 通过语音输入告诉机器人需要识别和射击的旋转靶ID和移动靶ID，代替手动修改代码中的ID号。
+ **核心特征：**
    - 需要两个程序文件（压缩包中的）：`2026_shot_demo`（负责语音听写转写）和`2026_shot_target`（负责ID映射和分发）
    - 触发流程：
        1. 主程序启动时，在终端显示“输入1继续”，输入1后，主程序向话题`/audio_topic`发消息（触发语音功能）
        2. 触发成功后，机器人会语音播报“比赛开始，开始录音”
        3. 参与者在录音时间内说出目标ID（如“1号6号”）
        4. 录音解析后，得到汉字文本（包含“一”“六”等）
        5. `2026_shot_target`程序解析汉字文本，将汉字映射到阿拉伯数字（1、2、3、4、5对应旋转码，6、7、8对应移动码）
        6. 映射完成后，将数字ID发到指定话题，主程序订阅后获得准确的ID
    - 如果语音识别不到有效数字，会语音播报“没有检测到1<sub>5的汉字”或“没有检测到6</sub>8的汉字”
+ **原理 / 机制：** 语音→转写→汉字→解析映射→数字ID→话题传输→主程序接收并使用该ID进行识别匹配
+ **典型应用 / 示例：**
    - 讲师举例：裁判告诉你旋转靶要打1号、移动靶要打6号，你就在录音时说“1号6号”，机器人自动解析并设置好
    - 讲师演示了主程序中的等待逻辑：触发后等待15秒（因为转写需要时间），如果机器性能差可延长到20秒
+ **判断关键词 / 答题用法：** “语音触发”“录音”“转写”“汉字映射到阿拉伯数字”“桥接的作用”
+ **考点提示 / 易错点：** 录音时背景噪音太大会影响识别准确率；语音模块需要提前调试好才能正常工作。

### 12. 整体启动脚本
+ **定义 / 含义：** 一个批处理脚本文件，按顺序启动所有必需的节点和程序，实现完整的目标射击任务流程。
+ **核心特征：**
    - 启动顺序（按讲师给出的脚本示例）：
        1. `base_control`（底盘控制，启动激光雷达等相关节点）
        2. `shooter_init`（射击模块初始化）
        3. `navigation.launch`（导航功能包）
        4. `camera_rviz.launch`（启动摄像头）
        5. `qr_code_launch`（二维码识别功能包）
        6. `object_detection.launch`（模板匹配程序）
        7. `tts_audio.launch`（语音合成/播报）
        8. `2026_shot_target`（语音ID映射程序）
        9. `2026_shot_demo`（语音听写程序）
        10. 最后启动主程序（任务代码文件）
+ **典型应用 / 示例：**
    - 讲师强调：一定不要忘了把主程序放到启动脚本里；坐标文件（点位文件）也要提前写好并放入
    - 运行该脚本后，整个目标射击流程就自动开始
+ **判断关键词 / 答题用法：** “启动底盘”“初始化设计模块”“启动导航”“启动摄像头”“启动二维码功能包”“模板匹配”“TTS/语音播报”“中间传输程序”“语音听写程序”
+ **考点提示 / 易错点：** 顺序不能乱，特别是射击模块初始化要在导航之前（或正确顺序），否则可能无法使用射击功能。讲师在脚本中明确写出了顺序。

## 四、例题 / 案例 / 应用场景整理
### 案例1：开箱与安装视频
+ **例子内容**：讲师播放B站上的M1ATK开箱安装视频，展示大箱子（无人车主主体）和小箱子（射击模块）的内容，演示如何安装铝柱、固定显示支架、连接电源线和HDMI线、开机连接键盘等步骤。
+ **对应知识点**：硬件组装流程（第一步）。
+ **讲师为什么用这个例子**：初学者需要用视频直观了解各部件长什么样、怎么拼装，只看文字讲解很难理解。
+ **判断依据 / 容易误设什么**：拼装顺序混乱可能导致螺丝拧错位置或铝柱方向不对；讲师强调“视频里是基础，后续注意事项更重要”。

### 案例2：充电器与电量显示
+ **例子内容**：讲师拿出底盘充电器（12.6V/3A）和射击模块充电器（8.4V/1A），指出底座充电口、启停键、电量显示的位置；给出底盘低于10.5V充电、射击模块低于7V充电的建议值。
+ **对应知识点**：充电器使用规范。
+ **讲师为什么用这个例子**：这是最常见硬件维护问题，用具体电压数值和实物展示让学生记牢。
+ **判断依据 / 容易误设什么**：容易把两个充电器搞混，导致电池过充或充不进电；讲师反复叮嘱“注意看电压电流”“不要弄混了”。

### 案例3：四个USB接口怎么插
+ **例子内容**：讲师指着机载电脑（NUC），指出左上方接口连激光雷达（数据线），橙色接口连射击模块（白色数据线），其他接口不要乱插；四个USB插混会导致“找不到接口”“找不到模块”的报错。
+ **对应知识点**：USB接口区分与热插拔禁令。
+ **讲师为什么用这个例子**：这是学生后期“经常遇到的一个问题”，很多报错其实只是线插错了，但初学者不知道。
+ **判断依据 / 容易误设什么**：把射击模块线插到了雷达接口，或反之；导致程序运行时激光雷达不工作或射击模块不响应。

### 案例4：HDMI线不能热插拔
+ **例子内容**：讲师用实物指出：机载电脑上的HDMI接口和显示器之间的线，如果带电插拔，屏幕会损坏无法正常显示；必须断电后再操作。
+ **对应知识点**：HDMI接口规范。
+ **讲师为什么用这个例子**：屏幕损坏是永久性硬件故障，且学生很容易“图省事”不关机直接拔线。
+ **判断依据 / 容易误设什么**：以为USB可以热插拔，所以HDMI也可以；实际上HDMI带电插拔产生的静电会烧坏驱动芯片。

### 案例5：地图文件名管理小技巧
+ **例子内容**：讲师说：建好地图A后如果不想被覆盖，就把`map`目录下的`my_lab.yaml`和`my_lab.pgm`改名为`my_lab2`；下次建新地图时会新建一个`my_lab`，两个地图并存且互不影响；想用地图A时，只需把`my_lab2`改回`my_lab`即可。
+ **对应知识点**：地图保存与文件名管理。
+ **讲师为什么用这个例子**：因为有同学直接改launch文件，结果跑程序时发现地图找不到；这个技巧能避免麻烦。
+ **判断依据 / 容易误设什么**：以为改launch文件里的default名字是正确方法；实际上改文件名更安全，因为不用动代码。

### 案例6：键盘控制键位演示
+ **例子内容**：讲师列出键盘控制建图时的键位：I=前进，逗号=后退，J=左转，L=右转，U=左前，O=右前，M=左后，句号=右后，大写字母=加速。
+ **对应知识点**：建图功能中的键盘控制。
+ **讲师为什么用这个例子**：新手如果不记住键位，操作小车时会乱按，影响建图质量。
+ **判断依据 / 容易误设什么**：把J和L搞反，把I和后按键搞混；导致小车走错路。

### 案例7：现场演示模板匹配识别
+ **例子内容**：讲师打开摄像头，终端显示“No object detected”；在摄像头前对物体“框一下”后，终端立刻显示“object 113”以及四个顶点坐标；接着再次拍照，终端显示“object 113”和“object 114”两个序号，说明识别到了两个模板。
+ **对应知识点**：模板匹配识别。
+ **讲师为什么用这个例子**：直观演示“如何让机器人认识一个目标”以及“识别结果长什么样”。
+ **判断依据 / 容易误设什么**：如果识别不到，可能是因为相机节点没打开；如果识别到两个序号，需要决定用哪一个，否则代码可能出错。

### 案例8：PID临界震荡调参演示
+ **例子内容**：讲师说：先调KP，使机器人针对目标左右摇摆（临界震荡状态），记下此时的KP值，再乘以0.7或0.8作为最终值；然后一点点加KI，直到瞄准变得丝滑。讲师还演示了用PID控制的小车微调瞄准的视频，车身非常细微地左右调整，然后稳定下来。
+ **对应知识点**：PI控制器调参方法。
+ **讲师为什么用这个例子**：用“临界震荡状态”这个具体现象作为评判标准，比抽象描述更容易理解。
+ **判断依据 / 容易误设什么**：调参时跳过KP直接调KI，或者KP调得过大导致震荡越来越严重（超调）；或KP过小导致响应极慢，半天瞄不准。

### 案例9：枪口物理偏移补偿
+ **例子内容**：讲师说：如果不管怎么调参数都打不准，可能不是软件问题，而是枪口本身是歪的（物理安装偏差）；这时候可以在代码里把中心点从`-320`改成`-319`、`-318`或`-323`，用偏移量来抵消物理偏移。
+ **对应知识点**：射击功能中的瞄准校准。
+ **讲师为什么用这个例子**：很多学生软件参数调了很久都不行，实际上只需要微调物理偏移量就能解决；这是一个典型的经验分享。
+ **判断依据 / 容易误设什么**：学生容易只调PID参数，没想到检查枪口是否正。

### 案例10：终点滑行进入
+ **例子内容**：讲师说：因为导航算法认为终点（角落）是障碍物，小车无法自动驶入；所以在代码中直接发速度指令（负X+正Y），让小车滑进去；如果从任务点三到终点距离远，需要加一个过渡点，先导航到过渡点，再滑进终点；滑行时间和速度值要调好，避免撞挡板。
+ **对应知识点**：终点处理。
+ **讲师为什么用这个例子**：这是比赛中最容易卡住的地方，学生经常以为导航能直接进去，结果小车停在终点外围来回打转。
+ **判断依据 / 容易误设什么**：滑行速度太小滑不动，速度太大直接撞墙；或者忘了加过渡点导致滑行轨迹不对。

### 案例11：语音控制“1号6号”
+ **例子内容**：讲师描述比赛场景：裁判告诉你旋转靶要打1号、移动靶要打6号；你在机器人发出“开始录音”后说“1号6号”；然后机器人自动解析并设置好对应的ID号。
+ **对应知识点**：语音控制模块。
+ **讲师为什么用这个例子**：用一个具体的比赛场景来说明语音模块的完整工作流程，学生更容易理解“什么时候说、说什么、会怎么样”。
+ **判断依据 / 容易误设什么**：录音时说错数字、背景噪音太大、或者说话太短导致转写失败；语音模块等待时间不够也可能导致解析失败。

### 案例12：启动脚本中忘了主程序
+ **例子内容**：讲师在讲解启动脚本时特意强调：“记得要把主程序放到启动脚本里”“不要忘了这个事”。
+ **对应知识点**：整体启动顺序。
+ **讲师为什么用这个例子**：因为每次比赛前都要跑一遍启动脚本，如果忘了放主程序，小车启动后什么也不会做。
+ **判断依据 / 容易误设什么**：学生通常记住了底盘、导航等节点，但容易忘记把最终的任务代码文件加进去。

## 五、对比辨析与易混点
| 对比项 | 模板匹配（环形码） | 二维码识别 |
| --- | --- | --- |
| 识别对象 | 环形靶（任务点一） | 旋转靶/移动靶上的二维码（任务点二/三） |

| 判断瞄准依据 | X方向误差（减320） | X方向+Y方向双误差 |
| 是否需要教学 | 需要（“框一下”） | 不需要（直接读ID） |
| 常见问题 | 模板序号与代码序号不对应 | 画面畸变导致数据飘忽不定 |


| 对比项 | P控制（比例控制） | PI控制（比例-积分控制） |
| --- | --- | --- |
| 控制效果 | 可能存在稳态误差 | 可消除稳态误差 |
| 参数 | 一个比例系数 | KP + KI |
| 响应速度 | 由比例系数决定 | 由比例系数决定，积分影响消除误差的时间 |
| 调参难度 | 简单，一个数 | 较复杂，需要先调KP再调KI |
| 适用场景 | 简单瞄准，要求不高 | 对精度要求高，要求更丝滑的瞄准（推荐） |
| 常见错误 | 比例系数太大导致震荡 | KI过大导致过冲；KP和KI调反顺序 |


| 对比项 | 旋转靶（任务点二） | 移动靶（任务点三） |
| --- | --- | --- |
| 靶子状态 | 静止但旋转 | 移动 |
| 识别方式 | 二维码识别 | 二维码识别 |
| 瞄准要求 | X和Y双方向对准 | X和Y双方向对准 + 快速跟踪 |
| 关键调参 | KP保持适中，避免震荡 | KP要调大（响应更快），保证跟踪性 |
| 易错点 | Y方向没判断，打空 | 响应太慢跟不上靶子移动 |

| 混用后果 | 可能烧毁充电电路或电池 | 充电不足或过充 |


## 六、高频考点 / 答题模板
1. **充电器判断模板：**  
“先看充电器上的电压电流标签，底盘用12.6V/3A，射击模块用8.4V/1A，不能混用。底盘低于10.5V充电、射击模块低于7V充电。”
2. **USB接口判断模板：**  
“机载电脑上的四个USB接口：左上方接激光雷达数据线，橙色（或指定）接口接射击模块白色数据线。插错会导致‘找不到接口’‘找不到模块’报错。”
3. **HDMI操作模板：**  
“显示器HDMI线必须在断电状态下插拔，带电操作会损坏屏幕，无法恢复。”
4. **地图保存模板：**  
“建图操作：点杠gmapping脚本启动，用键盘控制小车移动，保存用roslaunch robot_slam save_map.launch。要保留旧地图，就去map目录下改文件名，不要改launch文件里的default名称。”
5. **瞄准控制模板：**  
“判据：误差 = 识别目标中心X值 - 320（像素中心），当误差 > 阈值（如10像素）时继续旋转瞄准，当误差 < 阈值时认为对准，执行射击。如果枪口有物理偏移，可以微调减去的数值（如-318或-323）。”
6. **PID调参模板：**  
“先调KP使系统处于临界震荡状态（来回摇摆），记录该KP值后乘以0.7~0.8作为最终KP值；再一点点增加KI直到消除稳态误差，使瞄准丝滑。注意设限幅避免速度过大。”
7. **终点处理模板：**  
“用导航无法直接进入终点区域，改用速度指令（线性位移X、Y）让小车从过渡点滑行进入终点。滑行速度和时间需调试，避免撞墙。”
8. **语音控制模板：**  
“主程序触发语音：输入1后触发audio_topic，机器人开始录音；参与者在录音期间说出目标ID（如‘1号6号’）；转写为汉字后由target程序映射为数字ID（1<sub>5旋转码，6</sub>8移动码）；最终传给主程序进行识别和射击。等待时间约15~20秒。”
9. **启动脚本模板：**  
“启动顺序：底盘控制→射击模块初始化→导航→摄像头→二维码识别→模板匹配→语音播报→ID映射→语音听写→最后启动主程序。注意不要漏掉主程序。”
10. **单独调试模板：**  
“复制功能代码，只保留当前调试区域的识别回调函数，删除导航去任务点的代码；原地启动，只测试瞄准和射击逻辑，排除其他区域干扰。这是定位问题的第一步。”

## 七、最小复习清单
+ 记住底盘充电器（12.6V/3A）与射击模块充电器（8.4V/1A）的区别，以及各自的最低充电电压
+ 记住机载电脑上四个USB口的用途（左上方激光雷达，橙色射击模块），不要插混
+ 记住HDMI线绝对不能热插拔，必须断电
+ 记住建图保存地图时，不要改launch文件里的名字，要去map目录下改文件名为别的
+ 记住键盘控制键位：I前、逗号后、J左转、L右转、U左前、O右前、M左后、句号右后
+ 记住模板匹配识别后终端显示的`object 数字`就是模板序号，要与代码里的序号一致
+ 记住二维码识别返回X和Y两个方向的偏移量，旋转靶需要X和Y同时对准
+ 记住PID调参先调KP到临界震荡再衰减，后调KI；调参时速度限幅不能忘
+ 记住瞄准误差判断：误差 > 阈值继续瞄，误差 < 阈值开火
+ 记住终点进不去时用速度指令（X负Y正）滑进去
+ 记住单独调试方法：只留一个区域的功能代码，删掉导航部分
+ 记住语音控制流程：触发→录音→转写→映射→ID发送→主程序接收
+ 记住启动脚本顺序和不要漏了主程序
