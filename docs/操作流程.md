## 一、硬件检查（每次开机）

确认 USB 线没有插混：
- 左上方 USB → 激光雷达
- 橙色 USB → 射击模块
- HDMI 线严禁热插拔

```bash
# 查看串口设备
ls /dev/abot /dev/shoot /dev/rplidar
```

### 4.3 记录坐标

把小车精确停到每个任务点区域内（38cm × 32cm），然后：

```bash
# 查看当前 map 坐标
rostopic echo /amcl_pose -n 1 | grep position
```

把 x, y 值填入 `src/robot_slam/config/competition_2026_route.yaml` 中对应点的坐标。

**需要标定的点：**
- 起点位置
- 中继点 A、B、C、D（合理路径，避开禁行区和围挡）
- 任务点 1 中心 + 四个边界
- 任务点 2 中心 + 四个边界
- 任务点 3 中心 + 四个边界
- 终点位置

标定完成后推送到 GitHub。

## 八、AR 与射击模块单独测试

### 8.1 AR 标签识别

启动摄像头和 AR 标签检测后执行：

```bash
rostopic hz /usb_cam/image_raw
rostopic echo /ar_pose_marker
```

在 RViz 和终端中确认标签 ID 与比赛现场标签一致。

### 8.2 射击模块单发诊断

确认射击模块已通电、枪口朝向安全挡板，且没有启动 `competition_control`、
旧版 `shoot_control` 或 `shoot.py`。然后执行：

```bash
ls -l /dev/shoot
readlink -f /dev/shoot
fuser -v /dev/shoot

cd ~/freeze_ros/ros_shoot_2026
python2 src/robot_slam/scripts/shoot_demo.py
```

正常输出应包含：

```text
fire: wrote 8/8 bytes
stop: wrote 8/8 bytes
Test pulse sent.
```

该输出只能证明操作系统已经将命令写入串口，不能证明射击机构物理动作成功。
如果字节数正常但机构无动作，检查射击模块独立供电、USB 接口、`/dev/shoot`
是否指向正确串口，以及机构自身状态。

## 九、常见问题

| 现象 | 排查 |
|---|---|
| 找不到激光雷达 | USB 线插错了，换到 NUC 左上方 USB |
| 找不到射击模块 | 橙色 USB 线没插好 |
| 小车不移动 | `rostopic echo /cmd_vel` 检查是否有速度指令 |
| 导航不工作 | 地图是否加载、AMCL 初始位姿是否设置 |
| 模板匹配不识别 | 环形靶模板序号和代码里 `data.z == 34` 是否对应 |
| AR 标签不识别 | `rosrun rqt_reconfigure rqt_reconfigure` 调 ar_track_alvar 参数 |
| 多次打不准 | 检查枪口物理偏移，微调 `competition_control.py` 里的 `-320` 偏移量 |
| 终点进不去 | 调大 `_slide_into_end()` 里的速度或持续时间 |
| 语音识别失败 | 麦克风是否插好、背景噪音是否过大 |
