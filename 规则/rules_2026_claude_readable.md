## 1. 项目设置背景

该比赛主要围绕机器人智能控制领域，开展机器人定位、导航、视觉识别、人机交互等技术研究。通过比赛可以锻炼学生的综合创新实践能力，同时提高智能机器人控制、传感、驱动等方面的技术水平。

比赛涉及的专业知识和技能包括：

- 自动控制
- 单片机编程
- 数字电路
- 伺服电机驱动
- 机器人操作系统
- C / C++ / Python 编程
- 传感器技术
- 激光 SLAM
- 深度学习
- 人机交互

## 3. 参赛机器人 / 道具要求

参赛机器人需要满足附表要求。机器人可以自制。自制平台需要在省级比赛（预选赛）报名截止前一周内，与赛项负责人确认是否满足参赛要求。没有经过书面确认的机器人不能参赛。参赛队也可以咨询赛项负责人使用推荐机器人平台。

### 3.1 机器人参数要求表

|---|---|

| 负载 / 负重 | > 10 kg |

### 3.2 平台认证要求

参赛队赛前需要将参赛机器人技术参数发送到指定联系邮箱，进行参赛平台认证。认证通过后会统一发送认证通过说明文件。通过认证的参赛队才可以进入赛前检录环节。

机器人平台认证材料应包括：

- 机器人尺寸测量
- 机器人测量视频
- 机器人详细硬件介绍
- 主控制器型号和参数
- 执行控制器参数
- 传感器参数
- 电机参数
- 轮距等参数
- 软件架构及方案
- 硬件原理图

提交形式：

- 统一整理为 Word 文件发送到指定邮箱。
- 邮件内容需要体现：队长及队员姓名、学校、参赛队名称、所报名赛项。

时间要求：

- 资格认证截止时间为省级选拔赛举办日期向前推算 7 个自然日当天 17:00 前。

### 3.3 机器人扩展要求

在满足规则的前提下，可以对机器人的机械和传感器进行扩展。

扩展传感器要求：

- 扩展传感器需要经过赛项负责人认证；或
- 使用由用户完全自主自制的传感器；
- 未经组委会认证的扩展传感器，可能导致取消比赛资格。

### 3.4 安全要求

任何参加比赛的机器人都必须安全操作，不得对人和环境造成危害。

安全要求包括：

- 每台机器人都要将电源开关设置在外壳上容易接近的位置。
- 如果裁判认定参赛机器人存在安全隐患，经警示仍不修改，裁判有权取消参赛资格。

## 5. 任务规则与得分标准

总分为 100 分。

| 序号 | 任务内容 | 分值 |
|---|---|---:|
| 1 | 语音发布任务信息 | 10 |
| 2 | 到达任务点 1 | 10 |
| 3 | 击中 1 号点位前方环形标靶 | 20 |
| 4 | 到达任务点 2 | 10 |
| 5 | 击倒 2 号点位前方的任务标靶 | 15 |
| 6 | 到达任务点 3 | 10 |
| 7 | 击倒 3 号点位前方的任务标靶 | 15 |
| 8 | 到达终点区域 | 10 |
| 9 | 技术文档或现场答辩 | 10 |

### 5.1 答辩与文档限制

- 答辩分不足 3 分：不参与一、二等奖评审。
- 答辩分不足 6 分：不参与一等奖评审。
- 技术文档重复率超过 30%：不参与一、二等奖评审。

### 5.2 到达判定与成绩取值

- 机器人到达任务点或终点时，如果未完全进入任务点内，裁判根据实际情况酌情给分。
- 每支队伍有两次比赛机会。
- 最终成绩取两次比赛中的最高分。

### 5.3 同分排名规则

如果出现 2 个或 2 个以上队伍同分，则根据比赛终止前的比赛用时确定排名。

- 用时较少的队伍排名靠前。
- 比赛过程中，参赛队可以主动要求放弃比赛，以获得较短的比赛终止时间。

### 5.4 省赛 / 国赛通知

省赛和国赛会通过赛前会议发布通知。

## 6. 比赛流程

### 6.1 赛前准备

- 所有参赛成员需要关注 B 站官方账号：https://b23.tv/4J19xwL
- 赛前会议会在该账号下进行直播。
- 所有参加任务挑战项目的队伍，报名前队长务必加入 QQ 群。
- 如果因未加群导致信息发布不对等，后果自负。
- 联系方式中的 QQ 群加入一个即可。
- 裁判组会在比赛现场公布参赛队伍各任务点的目标靶任务信息。
- 每支参赛队比赛前有 2 分钟准备时间。
- 准备好后，将机器人放至出发区域，并示意裁判比赛。
- 裁判确认比赛开始后，参赛队启动机器人。

### 6.2 比赛过程

比赛开始后：

1. 机器人从起点出发。
2. 机器人需要进入每个任务点。
3. 机器人在地面投影完全进入任务点，即判定为到达。
4. 到达任务点后，机器人自行瞄准射击。
5. 在瞄准射击过程中，机器人不可进入禁行区域。

### 6.3 比赛结束条件

每场比赛发生以下情况之一，则比赛结束：

1. 参赛队员举手示意结束比赛。
2. 机器人完全进入“终点”区域。
3. 机器人在比赛过程中触碰到围挡。
4. 裁判宣布比赛开始后，机器人 30 s 未开始运动。
5. 机器人运行过程中，参赛队员进入场地。
6. 比赛过程中，裁判组有权根据机器人运行状态宣布比赛结束。例如：机器人程序死机，或机器人超过 20 s 状态未发生变化。
7. 涉及答辩提问环节时，如果在比赛过程中视角出现非本参赛队队员，则比赛结束，成绩为 0 分。

### 6.4 单场限时

- 每场比赛总用时不超过 2 分钟。
- 裁判宣布比赛开始时开始计时 2 分钟。
- 2 分钟计时结束则比赛结束。
- 只记录 2 分钟内的成绩。

## 8.1 必须重点检查的工程模块

| 规则要求 | 对应工程模块 / 文件类型 | 需要检查的问题 |
|---|---|---|
| 起点出发、到达 1-3 任务点、到达终点 | navigation / planner / waypoint / move_base / path / state_machine | 是否有任务点坐标配置；是否有状态机控制顺序；是否能记录到达判定 |
| 麦克纳姆轮、全向移动 | chassis / base_controller / cmd_vel | 是否支持全向运动；速度限制是否不超过规则和实际安全要求 |
| 语音发布任务信息 | voice / speech_recognition / audio / command_parser | 是否能识别任务编号；是否能把语音命令转换为任务序列 |
| 环形靶、旋转靶、移动靶识别 | vision / detector / target_recognition / camera | 是否有不同靶标类型识别；是否区分 1、2、3 任务点目标 |
| 自行瞄准射击 | gimbal / shooter / fire_control / ballistic | 是否支持瞄准、锁定、射击；是否有安全开关和发射条件判断 |
| 不能进入禁行区域 | planner / costmap / safety_zone | 是否配置禁行区；路径规划是否避开禁行区域 |
| 触碰围挡比赛结束 | localization / boundary_check / emergency_stop | 是否有边界检测；是否限制坐标范围 |
| 30 s 未运动结束 | task_state_machine / watchdog | 是否有启动后运动状态检测；是否有超时机制 |
| 超过 20 s 状态未变化可能被终止 | watchdog / state_monitor | 是否有状态变化检测；是否能在卡死时恢复或放弃 |
| 总用时 2 分钟 | task_manager / timer | 是否有全局倒计时；是否有比赛结束状态 |
| 两次比赛取最高分 | 非实时控制，偏比赛策略/日志 | 是否记录每次运行成绩和日志 |
| 技术文档 / 现场答辩 | docs / README / architecture diagrams | 是否有系统架构、硬件参数、软件架构、算法说明 |
